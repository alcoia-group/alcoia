## 15 November 2026: cards back off when turned away, "how often" beta question
- Within one reading (page), the policy has two steps (`intervention-policy.js`, `recordDismissal` / `recordSnooze` return `'reduced'` or `'stopped'`). Fewer cards: after 3 closes without an answer on the page, the raised dismissal bar, or a snooze; the gap between automatic cards doubles and a question needs the raised confidence. No more cards: any further close or snooze; no automatic card of any kind (nor the end-of-reading quiz offer) on that page; reader-initiated help still works; `reset()` starts over. The reader gets a status line (`cards.reduced` / `cards.stopped`, 12 languages). Reading signals the class view uses are unaffected (struggle outcomes are reported before the policy is asked; smooth rows come from paragraph reads). Placeholders: 3, x2.
- BETA-FEEDBACK: the end-of-reading beta card first asks "How often did Alcoia interrupt you on this page?" (Too often / About right / Not often enough), sent as `interruptions` with counts only (cards shown, closed, snoozes, quiet stage), then the existing "bad time" question.

## 19 November 2026: challenge questions for readers who are doing well, "check it against the text"
- The challenge level (adversarial: a counterexample or a critic's objection to one of the author's claims, answered in the reader's own words, never graded) was reachable only after systematic overconfidence, so almost nobody saw it. Now also, once per session (`epistemic-engine.js`, `nextLevel`), after a correct scenario or free-recall answer about a paragraph that ARGUES for a position. Factual paragraphs (definitions, procedures, reference and how-to text, anatomy, maths) keep the old ladder exactly. It replaces the next question, never adds one. `argument-cues.js` (`hasArgumentCues`, English stance words only, plain modal verbs like "should"/"must" deliberately not counted; other languages keep the old ladder) sets `identity.argues` in `host.js computeIdentity`. Still never after a wrong or inconclusive answer; Teaching Intent depth `recall` still caps it.
- Explanation and repair cards end with one muted line, `card.checkText` (12 languages): "Check it against the text: does the passage say the same?"
- The server now tells explanations to present opinions as the author's view (alcoiaServer `ATTRIBUTION_RULE`).
- Not verified in a browser or with real readers.

## 20 November 2026: scrolling boxes (orchestrator `scrollRoot`)
`createOrchestrator` takes an optional `scrollRoot`, a function returning the element that scrolls instead of the window (or null). The scroll listener is now a capture listener on the document that accepts the window or that one element and ignores every other scrolling element, so pages without the option behave as before. Why: the workspace's full-screen Word and PDF view makes the reading area a fixed scrolling box, so the window never scrolls and never fires `scroll`; the active paragraph then only moved on the 5 s idle tick and scroll speed read 0. The workspace must pass `scrollRoot: () => (document.documentElement.classList.contains('is-fullscreen') ? document.querySelector('.annotator') : null)` in `detection/boot.js` (not done in this repo). The reading line itself (40% of `window.innerHeight`) is unchanged: it is measured against the whole window, not the visible document area. Verified by unit tests (a scroll in the named box moves the active paragraph; another box and the no-option case are ignored; the box test fails without the capture phase). Not verified in a browser.

## 22 November 2026: more than one card per paragraph, and a self-report is always answered
- **Up to 3 automatic cards on one paragraph** (`MAX_CARDS_PER_PARAGRAPH`, `intervention-policy.js`; `seenParagraphs` is now a count). It was one. A reader can need help on the same passage more than once. The gap between cards (3 minutes), the open-card check and every other limit still apply, and the question comes first as before: a later card is a retrieval at the learner's level unless their evidence already says explain or repair. The pretest, retention and content-trigger paths still treat a paragraph that has had any card as taken.
- **A later card is a different kind of help** (`host.js` `paragraphHelp`, `explanation-style.js`): the layouts already used on this paragraph, and one that failed a transfer check, are avoided while another is left; a connection note ("relate") is not repeated; a learner with no profile (signed out, memory off) gets a layout from the closed list on the second card, the first stays the ordinary prompt. When every layout with results has been used, one with no results yet is tried.
- **A self-report overrides the limits on automatic cards** (the decision carries `selfReported: true`): the 3-minute gap, "fewer cards" and "no more cards" stages, the dismissal and wrong-answer back-offs, a card kind the learner usually turns away, the per-paragraph cap, and a learner estimate that says a question would add nothing. What still holds: one card on screen at a time, and the server's rate limits. A card the reader asked for does not start the gap before the next automatic card and does not count toward the paragraph cap. What kind of help it gets (question, explain, repair, simplify) is decided as for any card.
- The session cap (`SESSION_CAP_ENABLED`) is off, as before.
- Verified: extension suite (2049 passed), new policy tests for each override and for the cap, a host test for a different style on a repeat (fails without the paragraph memory). Not verified: in a browser, with a real reader over several cards. Thresholds (3 cards, same gap) are provisional.

## 25 November 2026: repair by kind of difficulty

## 25 November 2026: plainer wording on later cards
The second explanation or repair card on a paragraph asks the server for `plainness: 'plain'` (everyday words, short sentences, jargon explained) and the third for `'basic'` (no jargon, smallest steps, one daily-life example). The first card is unchanged. Counted per paragraph in `host.js` (`#n` entries in `paragraphHelp`). Verified by host tests only; not against a real model.
