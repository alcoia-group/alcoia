## 19 November 2026: challenge questions for readers who are doing well, "check it against the text"
- The challenge level (adversarial: a counterexample or a critic's objection to one of the author's claims, answered in the reader's own words, never graded) was reachable only after systematic overconfidence, so almost nobody saw it. Now also, once per session (`epistemic-engine.js`, `nextLevel`), after a correct scenario or free-recall answer about a paragraph that ARGUES for a position. Factual paragraphs (definitions, procedures, reference and how-to text, anatomy, maths) keep the old ladder exactly. It replaces the next question, never adds one. `argument-cues.js` (`hasArgumentCues`, English stance words only, plain modal verbs like "should"/"must" deliberately not counted; other languages keep the old ladder) sets `identity.argues` in `host.js computeIdentity`. Still never after a wrong or inconclusive answer; Teaching Intent depth `recall` still caps it.
- Explanation and repair cards end with one muted line, `card.checkText` (12 languages): "Check it against the text: does the passage say the same?"
- The server now tells explanations to present opinions as the author's view (alcoiaServer `ATTRIBUTION_RULE`).
- Not verified in a browser or with real readers.

## 20 November 2026: scrolling boxes (orchestrator `scrollRoot`)
`createOrchestrator` takes an optional `scrollRoot`, a function returning the element that scrolls instead of the window (or null). The scroll listener is now a capture listener on the document that accepts the window or that one element and ignores every other scrolling element, so pages without the option behave as before. Why: the workspace's full-screen Word and PDF view makes the reading area a fixed scrolling box, so the window never scrolls and never fires `scroll`; the active paragraph then only moved on the 5 s idle tick and scroll speed read 0. The workspace must pass `scrollRoot: () => (document.documentElement.classList.contains('is-fullscreen') ? document.querySelector('.annotator') : null)` in `detection/boot.js` (not done in this repo). The reading line itself (40% of `window.innerHeight`) is unchanged: it is measured against the whole window, not the visible document area. Verified by unit tests (a scroll in the named box moves the active paragraph; another box and the no-option case are ignored; the box test fails without the capture phase). Not verified in a browser.
